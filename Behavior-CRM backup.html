Core Logic Specification

Project: Behavior-Driven CRM v2.1  |  Focus: Business Logic & Calculation Formulas

본 문서는 Behavior-Driven CRM을 구성하는 6대 핵심 지표의 산출 로직을 기술합니다. 각 지표는 단순한 통계가 아닌, 영업 현장의 비효율을 제거하고 성과를 공정하게 평가하기 위해 설계되었습니다.

2. HIR (High-Impact Rate) Efficiency

단순히 '몇 번 방문했나(Count)'가 아니라, '매출에 기여하는 유효한 행동을 했나(Impact)'를 측정하는 지표입니다.

HIR = Σ ( 행동가중치 × 질적점수 × 영향력계수 ) / 총활동수 × 100
• 행동가중치: 방문(3.0) > 설명회(2.5) > 전화(1.0) 등 난이도 반영 • 질적점수: GPS 인증, 체류시간, 자료 활용 여부에 따른 보정 (0.8 ~ 1.2) • 영향력계수: 과거 데이터 분석 결과, 해당 제품의 매출 상승과 상관관계가 높은 행동일수록 가산점 부여
💡 Logic Rationale (설계 의도) 영업사원이 실적을 채우기 위해 의미 없는 '안부 문자'나 '단순 방문'만 반복하는 허수 영업(Abuse)을 방지하고, 회사가 전략적으로 중요하게 생각하는 행동(예: 신약 설명회)을 유도하기 위함입니다.

3. RTR (Relationship Temperature Rate) Health

고객과의 관계가 현재 얼마나 뜨거운지(Hot) 혹은 식었는지(Cold)를 온도(Temperature)로 나타냅니다.

RTR = Σ ( 감정점수 × 시간감쇠계수 )
• 감정점수(Sentiment): 활동 기록 내 키워드 분석 (긍정 +10 ~ +20 / 부정 -10 ~ -30) • 시간감쇠(Time Decay): 최근 활동일수록 100% 반영, 오래될수록 영향력 감소
// 시간 경과에 따른 가중치 감소 로직 (Time Decay) function calculateTimeDecay(daysPassed) { if (daysPassed <= 7) return 1.0; // 1주일 이내: 생생함 (100%) if (daysPassed <= 14) return 0.8; // 2주일 이내: 약간 식음 (80%) if (daysPassed <= 30) return 0.5; // 1달 이내: 흐릿함 (50%) return 0.1; // 1달 경과: 관계 리셋 (10%) }
💡 Logic Rationale (설계 의도) 과거에 아무리 친했어도 최근에 방문하지 않았다면 관계는 식습니다. 이를 수치화하여 고객 이탈(Churn)이나 경쟁사 진입 징후를 조기에 포착합니다.

4. BCR (Behavior Consistency Rate) Routine

영업 활동이 얼마나 꾸준하고 규칙적으로 이루어지는지 평가하여, '월말 몰라치기' 영업을 방지합니다.

BCR = (총량점수 × 0.4) + (규칙성점수 × 0.6)
• 총량점수: 목표 콜 수 달성률 • 규칙성점수: 방문 간격의 표준편차(Standard Deviation) 역수
💡 Logic Rationale (설계 의도) 활동량(Quantity)만 평가하면 월말에 몰아서 방문하는 부작용이 생깁니다. 표준편차를 도입하여 매일 꾸준히 활동하는 영업사원이 더 높은 점수를 받도록 설계했습니다. 이는 재고 관리 효율화와도 직결됩니다.

5. PHR (Proactive Health Rate) Pipeline

모든 영업 미팅이 '다음 약속(Next Step)'으로 이어지는지 확인하여, 파이프라인의 건전성을 측정합니다.

PHR = ( 유효한 Next Action 수 / 총 활동 수 ) × 100
function validateNextAction(actionDate, note) { // 1. 날짜가 미래인가? if (actionDate <= new Date()) return 0; // 이미 지난 날짜는 무효 // 2. 구체적인 계획이 있는가? (단순 인사는 제외) if (note.length < 5 || isAbstract(note)) return 0; return 100; // 유효한 파이프라인으로 인정 }
💡 Logic Rationale (설계 의도) "다음에 밥 한번 먹자"는 영업이 아닙니다. 구체적인 날짜와 용건이 있는 약속만을 유효 데이터로 인정하여, 기약 없는 미팅(Dead Lead)을 최소화합니다.

6. Field Growth Rate (필드 성장률) Market Share

단순 매출액 증가가 아닌, 실질적인 시장 장악력(처방 수량)의 성장 추이를 측정합니다.

Growth Rate = (처방량 성장률 × 0.6) + (매출액 성장률 × 0.4)
// 성장률 가중 평균 계산 로직 let quantityGrowth = calcGrowth(currentMetrics.totalQuantity, comparisonMetrics.totalQuantity); let revenueGrowth = calcGrowth(currentMetrics.totalRevenue, comparisonMetrics.totalRevenue); // 처방량(Q)에 60%, 매출액(P)에 40% 가중치 부여 const fieldGrowthRate = (quantityGrowth * 0.6) + (revenueGrowth * 0.4);
💡 Logic Rationale (설계 의도) 약가 인하 등 외부 요인으로 매출액(Price)은 변동될 수 있습니다. 하지만 처방 수량(Quantity)은 영업사원의 노력이 직접 반영된 결과입니다. 따라서 처방량(Q)에 더 높은 가중치(60%)를 두어 실질적인 시장 지배력을 평가합니다.

7. Prescription Index (처방 기반 성과지수) Fairness

병원 규모와 영업 난이도를 고려하여 성과를 공정하게 보정(Normalization)한 지표입니다.

Index = (가중 처방량 × 0.7) + (성장률 점수 × 0.3)
// 병원 타입별 가중치 적용 (난이도 보정) const accountWeight = account.type === 'TERTIARY' ? 1.5 : // 상급종합병원 (난이도 최상) account.type === 'GENERAL' ? 1.2 : // 종합병원 1.0; // 의원/약국 (기본) // 최종 가중치 계산 const finalWeight = accountWeight * priceWeight; const weightedQuantity = prescription.quantity * finalWeight;
💡 Logic Rationale (설계 의도) 동네 의원에서의 100건 처방과 대학병원에서의 100건 처방은 투입되는 노력과 난이도가 다릅니다. 상급종합병원에 1.5배의 가중치를 부여함으로써, 어려운 영업을 성공시킨 담당자를 더 높게 평가하는 공정한 보상 체계를 마련했습니다.
